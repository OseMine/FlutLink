### F1 — [Bug, Blockierer] `admin_edit_user` lehnt Key `enabled` ab, Button im AdminPanel schlägt immer fehl

- **Datei/Funktion:** `src/components/AdminPanel.vue:143-145` (`toggleEnabled` →

- **Problem:** Der „Aktivieren/Deaktivieren"-Button (Zeile 306) im AdminPanel
  kann prinzipiell nie erfolgreich sein. Backend-Whitelist kennt nur
  `displayname, email, quota, password, language, locale`.
- **Fix-Vorschlag:** Entweder `enabled` in `ADMIN_EDIT_KEYS` aufnehmen
  (`ocs::update_user` unterstützt `enabled` seit Nextcloud 25) oder den Button
  aus dem UI entfernen. Nicht beides divergieren lassen.

### F2 — [Bug, Blockierer] Total-Timeout von 60 s (HTTP-Client) bricht große WebDAV-Transfers ab; 30 s im Updater

- **Datei/Funktion:** `src-tauri/src/state.rs:112-113`
  (`Client::builder().timeout(Duration::from_secs(60))`) und
  `src-tauri/src/updater.rs:526-527` (`.timeout(…30…)`).
- **Problem:** reqwest `.timeout()` ist ein **Total-Timeout über die gesamte
  Transaktion inkl. Body**. Alle WebDAV-Dateioperationen (Upload/Download via
  `webdav::put_file`/`get_file`, Sync-Engine, Datei-Commands) laufen über den
  60-s-Client → Uploads/Downloads von Dateien, die länger als 60 s brauchen,
  brechen ab. Der Updater-Download von >30 s (typisch bei 100+ MB-Installern)
  bricht ab; die partielle Datei bleibt liegen (siehe F3).
- **Fix-Vorschlag:** `connect_timeout` + `read_timeout` (reqwest 0.13) statt
  Gesamt-`timeout`, oder Timeout nur für Nicht-Streaming-Requests setzen.
  Mindestens separat `read_timeout` für Datei-Transfers verwenden.

### F3 — [Bug, minor] Updater räumt partielle Downloads bei Fehlern nicht auf

- **Datei/Funktion:** `src-tauri/src/updater.rs` `download_update` (Stream-
  Schleife um Zeile 260-283).
- **Problem:** Bricht der Stream ab (vgl. F2), bleibt die `.part`/Tmp-Datei im
  Cache liegen; beim nächsten Versuch wird neu begonnen. Analog zu B18 (war für
  `get_file_as` behoben, hier nicht).
- **Fix-Vorschlag:** Im Fehlerpfad die partielle Datei löschen (wie
  `get_file_as`).

### F4 — [Bug, mittel] Doppel-URL-Encoding des `path`-Feldes in `ocs::create_share` (Share mit Sonderzeichen schlägt fehl)

- **Datei/Funktion:** `src-tauri/src/nextcloud/ocs.rs:262-273`
  (`let encoded_path = encode_segments(rel_path); … req.form(fields)`) +
  `src-tauri/src/nextcloud/mod.rs:23-24` (`req.form(fields)`).
- **Problem:** `encode_segments` produziert bereits `%20`-Sequenzen; der
  form-url-encoded POST (`req.form`) encodiert `%` erneut zu `%25` und `/` zu
  `%2F`. PHP dekodiert einmal → der Server erhält wörtlich `My%20Folder` statt
  `My Folder` → OCS-Fehler („path not found") für alle Dateinamen mit
  Leerzeichen, Umlauten, `#`, `&`, `+`, `?`. Einfache Pfade ohne Sonderzeichen
  funktionieren zufällig.
- **Fix-Vorschlag:** Raw-Pfad (decoded) ins Formular geben; das Encoding
  übernimmt `req.form`. Ggf. einen Roundtrip-Test ergänzen.
- **Hinweis:** `webdav::list`/`get_file` sind korrekt, weil dort nur die URL
  (einmaliges Encoding) betroffen ist; nur das Form-Feld ist doppelt encoded.

### F5 — [Bug, minor] About-Tab zeigt hartkodierte Version „0.1.0"

## Neue Befunde (Lauf 3, Fokus UI)

### U1 — [Bug, mittel] Umbenennen in Unterordnern schlägt immer fehl (`webdav_rename` baut Pfad ohne führenden Slash)

- **Datei/Funktion:** `src-tauri/src/commands.rs:454-477` (`webdav_rename`),
  ausgelöst von `src/components/FileExplorer.vue:162-177` (`doRename`) über
  `src/stores/files.ts:111-119` (`renameEntry`).
- **Problem:** `let parent = path.rsplit('/').nth(1).unwrap_or("");` liefert
  für `/Documents/report.pdf` den String `Documents` (ohne führenden Slash).
  `new_path = format!("{}/{}", parent, new_name)` → `Documents/neu.txt`.
  `validate_dav_path` (commands.rs:342-359) verlangt aber
  `path.starts_with('/')` → immer `AppError` „Path must be absolute".
  **Umbenennen funktioniert nur für Dateien/Ordner im Wurzelverzeichnis**
  (dort ist `nth(1)` = `""`). Verifiziert per Logiksimulation (Python) und
  Code-Lese-Prüfung.
- **Fix-Vorschlag:** `let parent = path.rfind('/').map(|i| &path[..i]).unwrap_or("")`
  (behält den Slash), oder direkt `path.rsplit_once('/')`:
  `let new_path = format!("{}/{}", &path[..i], new_name)`.
- **Test:** Unit-Test für `validate_dav_path` + neue_pfad-Berechnung mit
  `"/Documents/report.pdf"` und `"/report.pdf"`.

### U2 — [Bug, UI] Nach Konto-Wechsel über das UI erscheinen mehrere Konten gleichzeitig als „aktiv"

- **Datei/Funktion:** `src/stores/accounts.ts:90-101` (`switchTo` → `sync()`)
  i. V. m. `src-tauri/src/commands.rs:260-273` (`account_switch`).
- **Problem:** `account_switch` gibt nur das eine (neue) aktive Konto zurück
  und emittiert **kein** `accounts-changed`-Event (nur der Tray-Pfad
  `lib.rs:115-128` emittiert es). `sync()` (accounts.ts:22-29) mappt nur das
  zurückgegebene Konto; die `isActive`-Flags der übrigen Konten im
  Pinia-Array bleiben auf dem alten Wert. Ergebnis: Nach dem Wechsel zeigt
  die AccountBar (`AccountBar.vue:80-83`) und das Konto-Menü
  (`App.vue:187-189`) das vorherige **und** das neue Konto als aktiv
  (markiert), bis die App neu lädt.
- **Fix-Vorschlag:** Entweder in `accounts.switchTo` nach Erfolg `await load()`
  statt `sync()` aufrufen (ein `account_list`-Roundtrip), oder im Backend
  `account_switch` (wie der Tray-Pfad) `app.emit("accounts-changed", ())`
  auslösen. Beides ist minimal-invasiv.

### U3 — [Bug/UX, mittel] Share-Link: Clipboard-Fehler zeigt „Fehler", obwohl der Link serverseitig erstellt wurde — URL geht verloren

- **Datei/Funktion:** `src/components/FileExplorer.vue:198-208` (`createLink`).
- **Problem:** Nach `files.createShare(...)` wird
  `await navigator.clipboard.writeText(url)` ausgeführt. Schlägt das
  Clipboard-Schreiben fehl (im Tauri-WebView — insbesondere Linux/WebKitGTK —
  ist `navigator.clipboard.writeText` nicht garantiert verfügbar bzw. kann
  ohne Berechtigung rejecten), landet der Status in `shareState` auf
  `"error"` → die UI zeigt ein rotes ✗ (Zeile 480), **obwohl der Share
  erstellt wurde**. Die erzeugte URL ist danach nirgends mehr abrufbar (kein
  zweiter Aufrufweg, kein Link-Tooltip).
- **Fix-Vorschlag:** Bei Clipboard-Fehler nicht auf `"error"` setzen, sondern
  `"done"` mit der URL behalten und die URL zusätzlich im Toast
  (`ui.toast(...)`) bzw. als Klick-zum-Kopieren-Element anzeigen. Alternativ
  `@tauri-apps/plugin-clipboard-manager` als explizite, permission-basierte
  API nutzen.

### U4 — [Bug, minor] `uploadFiles`: Guard `busyPath` ist wirkungslos, Mehrupload bricht beim ersten Fehler ab

- **Datei/Funktion:** `src/components/FileExplorer.vue:123-142` (`uploadFiles`)

- **Problem:** `busyPath.value = ""` (Z. 125) ist ein leerer String und damit

  während eines laufenden Uploads nicht (nur der Upload-Button ist über

- **Fix-Vorschlag:** `busyPath.value = "upload"` (nicht-leerer Token) oder
  besser ein `Set<string>`/Zähler; im Loop Fehler pro Datei sammeln und
  weitermachen, Toast nur bei mindestens einem Erfolg (oder pro Datei).
