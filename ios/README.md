# FlutLink iOS

TEST — iOS port created by **opencode**. Not a production build.

FlutLink mobile client for the FlutCloud server: file browsing, sharing and
user administration on iOS, built with Swift + SwiftUI and the same
FlutCloud-only policy as the desktop client — it connects exclusively to the
FlutCloud server (`FLUTCLOUD_URL`) and rejects servers that do not run the
FlutCloud Nextcloud app (`flutcloud-app/`).

> **This is a port.** The iOS app is a port of the FlutLink desktop client
> (Tauri/Rust + Vue) to Swift/SwiftUI. It was generated entirely by **opencode**
> and mirrors the desktop feature set — it is not a separate product and must
> stay behaviorally in sync with the desktop client.

## Feature parity with the desktop client

- **FlutCloud-only enforcement** — `FlutCloudApi.verifyServer` probes the
  `flutcloud` capability before an account is accepted.
- **Files** — WebDAV browsing (PROPFIND), upload (document picker),
  download + share via the iOS share sheet, folder creation, rename,
  delete, global search (SEARCH), virtual-link (`resources`/`parts`) pairing,
  share management (create public links, list existing shares, revoke),
  offline cache for folder listings with an "Offline — showing cached data"
  banner.
- **Admin** — OCS user administration: list/search, create, delete,
  enable/disable, quota presets, group management (view a user's groups,
  add/remove members, create groups).
- **Registration** — create a real account from the login screen (admin
  credentials via the OCS Provisioning API), then sign in with the new
  account's password.
- **Security** — tokens live in the iOS Keychain (kSecAttrAccessibleWhenUnlockedThisDeviceOnly),
  account metadata in UserDefaults, same split as the desktop keyring design.
- **Appearance** — the FlutCloud brand themes **OperationFlut** and
  **Deep Midnight** plus an **accent hue slider** (Settings → Appearance),
  matching the desktop `[data-theme]` palettes in `src/style.css`.

### Consciously not on mobile (product decision)

- **Two-way sync** — the desktop client's background sync engine
  (`src-tauri/src/sync.rs`) is a deliberate **desktop-only** feature.
  The same reasons as the Android port apply (sandbox restrictions,
  background execution limits, conflict UX on a small screen).
- **Auto-update** — iOS App Store / AltStore sideloading has its own
  update mechanisms; no self-updater is needed.

## Build

### Prerequisites

- macOS 14+ with Xcode 16+ and command-line tools
- [XcodeGen](https://github.com/yonaskolb/XcodeGen): `brew install xcodegen`

### Quick build

```bash
cd ios
xcodegen generate
open FlutLink.xcodeproj
# Build & run in Xcode (Cmd+R) or:
xcodebuild -scheme FlutLink -destination "generic/platform=iOS" build
```

### Unsigned IPA

```bash
chmod +x scripts/build-ipa.sh
./scripts/build-ipa.sh          # Debug build
./scripts/build-ipa.sh --release  # Release build
# Output: build/ios/FlutLink.ipa
```

The IPA is **unsigned** — a signing identity (or AltStore/Sideloadly) is
required to install it on a device.

### FlutCloud URL

The server URL is baked in at build time via `FLUTCLOUD_URL`:

```bash
export FLUTCLOUD_URL=https://your-server.example
xcodegen generate
xcodebuild -scheme FlutLink -destination "generic/platform=iOS" build
```

When a URL is set, the login screen locks the server field.
